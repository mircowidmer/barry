## 2. Threat model

- **Assets:** the safety promise (an Alert goes out when a Deadline passes and only the Adventurer can stop it); the live Trail, the destination and the Deadline; the Profile with its medical notes, and the contacts' addresses; the sessions; the budget and reputation of Resend and Twilio; the operator's machines and the secrets they hold.
- **Boundaries:**
  - The phone and PostgREST, through the publishable key and the user's JWT. Only `public` and `graphql_public` are exposed.
  - The Postgres roles `anon`, `authenticated`, `service_role` and the definers of `commands` and `private`.
  - `deliver`, with `verify_jwt = false`, gated by `DELIVER_SECRET` and the HMAC report token.
  - Twilio, Resend and Supabase Auth's SMTP; Open-Meteo and the SLF, which the phone now asks for the Conditions; Apple Maps for the place search; Cloudflare Turnstile.
  - barry.support on GitHub Pages; OpenFreeMap for tiles.
  - CI: the GitHub-hosted runners, and new, the self-hosted Mac `barry-mac`, which runs the code of every pull request that changes the native project.
- **Attackers:** another Adventurer reaches PostgREST and every command; an anonymous caller reaches `trail_map`, `deliver` and Auth; an Emergency Contact holds a token; someone near the phone reaches its storage and backups; anyone on GitHub can fork the public repository and open a pull request; the supply chain reaches npm, Deno and the Actions.

## 3. Findings

### SEC-1 · A pull request from a fork runs its own code on the self-hosted Mac barry-mac

**High** · CWE-829, CWE-494 · GitHub: Security hardening for GitHub Actions, "Hardening for self-hosted runners" · **certain** for the code execution, **likely** for what it reaches

**Where:**
- `.github/workflows/ci.yml:3-8`: the workflow runs `on: pull_request`, which includes pull requests from forks.
- `.github/workflows/ci.yml:159-161`:
  ```yaml
      # barry-mac, the self-hosted runner with the label ios, builds every push to main and every pull request, forks included.
      # The Actions setting that holds a fork's first workflow run for approval is the only gate before its code runs there.
      runs-on: ios
  ```
- The job then runs the pull request's own code on that machine: `npm ci` with its `package.json` and `postinstall` (`scripts/maplibre-worker.mjs`), `npx expo prebuild` with its config plugins (`plugins/`), `pod install` and `xcodebuild` with its native code and build phases. `scripts/changed-inputs.sh:8` sends exactly those pull requests there, because a change to `package.json`, `plugins/` or `modules/` counts as native.
- `e9acb91` (29 October) replaced `runs-on: ${{ github.event.pull_request.head.repo.fork && 'macos-26' || 'ios' }}` with `runs-on: ios`. The repository is public (`visibility: public`, forking allowed).

**Attack path:**
1. An attacker forks `mircowidmer/barry` and adds a `postinstall` line to `package.json`, or a config plugin, or a build phase.
2. They open a pull request. If they have had a pull request merged before, or the repository's setting asks approval only for first-time contributors and they are approved once (for example with a harmless first pull request), the run starts without anyone looking.
3. `npm ci` on `barry-mac` runs their script as the runner's user, with network access.

**Gain:** code execution on the operator's Mac. The runner is not ephemeral (`ci.yml:176-189` relies on it keeping `~/Library/Caches/ccache` and `~/Library/Caches/CocoaPods` between runs), so the attacker can stay: plant a launch agent, or poison the ccache and CocoaPods caches that every later build of `main` on that Mac uses. What else they reach depends on what the runner's user can read, which the repository does not say: if it is the operator's own account, that includes any checkout with `supabase/.env.hosted` (the hosted service-role key, `DELIVER_SECRET`, the Twilio and Resend keys), the Apple signing identities and the GitHub and Expo logins. With the hosted secrets, the attacker could claim and settle the outbox and so silence Alerts (priority 1). GitHub's own guidance: "We recommend that you only use self-hosted runners with private repositories. This is because forks of your public repository can potentially run dangerous code on your self-hosted runner machine by creating a pull request that executes the code in a workflow."

**Source:** docs.github.com, Security hardening for GitHub Actions, Hardening for self-hosted runners; docs.github.com, Approving workflow runs from public forks.

**Fix:** put the fork condition back (`runs-on: ${{ github.event.pull_request.head.repo.fork && 'macos-26' || 'ios' }}`, as in `9208fa3`). If forks should keep using the Mac, at least set **Settings › Actions › General › Approval for running fork pull request workflows** to "Require approval for all external contributors", run the runner as a dedicated macOS user that holds no secret and no checkout of the operator's, and make it ephemeral or wipe its caches after a fork's run.

**Outcome:** skipped, rule 2. Running forks on `barry-mac` is a decision the author made the day before (`e9acb91`, with the risk named in the comment), and the fix reverses it or changes repository settings.

### SEC-2 · The cached Adventure, the Trail buffer, the Check-in queue and the kept Conditions sit in a storage file that iOS backups include

**Low** · CWE-312, CWE-922 · MASVS-STORAGE-1, OWASP Mobile Top 10 2024 M9 · **certain** for the storage

**Where:**
- `src/lib/storage.ts:1-3`: `import 'expo-sqlite/localStorage/install'; export const storage = localStorage;`
- `src/lib/barry/adventure-cache.ts:3` (`barry.inProgressAdventure`), `trail-buffer.ts:12-13` (`barry.trailBuffer`, `barry.trailSent`), `check-in-queue.ts:16` (`barry.pendingCheckIns`) and, new since 28 October, `conditions.ts:15` (`barry.conditions`): the destination, the Deadline, the contacts' names and addresses, the last position, the unsent Trail readings, the waiting Check-ins, and the destination points of the last `KEPT` places rounded to `POINT_DECIMALS`.

**Attack path:** someone with an unencrypted Finder backup, the victim's iCloud backup or a jailbroken phone reads `Documents/SQLite/ExpoSQLiteStorage`.

**Gain:** where the Adventurer is headed and when they are due back, their contacts' addresses, the last part of their Trail, and the last five places they planned to go to, each to about a kilometre. No session: that is in the Keychain (`auth-storage.ts`).

**Source:** OWASP MASVS-STORAGE-1.

**Fix:** keep these values in the Keychain as well, or exclude the file from backup.

**Outcome:** skipped, rule 2. Moving data to another storage is the author's decision, and on 28 October the author kept the storage as it is.

## 4. Hardening notes

New:

- `src/lib/barry/client.ts:364-376`: Log Out and Delete Account clear the cached Adventure (`remember(null)`) and the session, but not `barry.conditions`, so the rounded points of the last five destinations stay on the phone after the account is gone. Nobody else sees them in the app, since Conditions show only for the signed-in Adventurer's own pin; only the file holds them (SEC-2). The spec's promise in `docs/spec.md:21` is about the server.
- `src/lib/barry/conditions.ts:89-107` and `:135-157` cast the Open-Meteo and SLF responses without checking their shape. A malformed answer throws and is caught (`at`, `.catch(() => null)`), so it shows as unavailable; only a provider or TLS compromise could send one, and it reaches no `eval`, link or HTML. The answers are bounded only by `fetchWithTimeout`'s ten seconds, not by size.
- `supabase/config.toml:209`: `sign_in_sign_ups = 300` for the local stack's e2e suite; `[remotes.hosted.auth.rate_limit]` (`:442-444`) keeps 30, so the relaxed value does not reach the hosted project.

Still standing from 28 October, unchanged: the default `EXECUTE` on `private` functions (unreachable, since neither role may use the schema); `net` usable by `anon` and `authenticated` (not exposed through the API); `private.tick_error` after account deletion; a claimed message still going out after its contact is removed; `!==` for `DELIVER_SECRET` (`kick.ts:4`) and the report token (`delivery-report.ts:33`); `minimum_password_length = 6`; `NSAllowsLocalNetworking` in every variant; custom schemes without universal links; `expo-dev-client`'s Metro link; the offline Check-in queue left after Log Out; `.github/dependabot.yml` with `package-ecosystem: ""`; no committed `deno.lock`; Actions pinned by tag, now including `maxim-lobanov/setup-xcode@v1` and `actions/cache@v4`; `pages: write` and `id-token: write` on the job that runs `npm ci` in `trail-map.yml`; `eas-cli@latest`; `AUTH_SMTP_PASS` uploaded to `deliver`; `sms-relay.mjs` on every interface; `.gitignore` without a plain `.env`; `docs/ci-simulator.md`'s service-role key; `pod install` and `brew install ccache` on `barry-mac` without a pinned version; the `zod` and `deepmerge` advisories in the Expo CLI.

## 5. Checked and safe

1. **Database:** no migration since `20261029090000_pace_updates.sql`, whose `private.pace_updates` and `private.guard_contact_address` are security definer with `search_path = ''` and revoked from `public`. Probes, with Adventurer A's Adventure Active and its Heads-up enqueued, as Adventurer B: reading `adventures`, `emergency_contacts`, `messages`, `position_readings`, `adventurer_profiles` and `delivery_failures` returned nothing of A's; `check_in`, `move_deadline`, `delete_adventure`, `record_trail` and `save_adventure` over A's id answered `not_found`; `save_adventure` with A's contact `unknown_contact`; updating A's contact and Profile changed no row; inserting a contact for A was refused by row level security; `claim_messages`, `report_delivery`, `message_facts` and `health` answered `permission denied`. As `anon`: `adventures` `permission denied`, `trail_map` with a guessed token `null`. A's Adventure stayed Active with its Deadline, and only its own Heads-up was queued.
2. **The Trail Map:** unchanged since 28 October: a 128-bit token per contact in the fragment, the page's Content-Security-Policy and `no-referrer`.
3. **`deliver`:** `/` and `/status` answer `401` without a secret and with a wrong one (probed). Fixed outbound hosts; the Deno tests pass.
4. **Auth:** hosted `sign_in_sign_ups = 30` and `email_sent = 30`, confirmations on, captcha on in `[remotes.hosted.auth.captcha]`, `secure_password_change = true`; the local relaxation stays local.
5. **The app:** the Conditions send Open-Meteo only the destination rounded to two decimals (`conditions.ts:58-61`, `:71-73`), built from numbers into a fixed `https` URL; the SLF URL takes only the app language, `en` or `de`; the bulletin link opens a fixed `whiterisk.ch` URL from `texts.ts`; no `WebView`, HTML or deep link takes their data. The privacy page names both providers.
6. **The web:** `web/index.html` and `web/privacy.html` gained only static text.
7. **Secrets:** the only key-shaped value in the history is the Turnstile site key in `eas.json`, public by design; `supabase/config.toml` holds local placeholders only; `git ls-files` lists no secret file (`.env.example` holds empty values).
8. **Supply chain and CI:** the new `changes` job passes the event name and base SHA through `env`, never inline; `ci.yml` has `permissions: contents: read` and uses no secret; `pr-description.yml` has `permissions: {}` and reads the title and body through `env`. The self-hosted runner is SEC-1.
9. **Documents:** no guide added since 28 October tells the reader to do something unsafe.
