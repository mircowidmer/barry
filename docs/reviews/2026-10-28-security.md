The three that matter most:

2. **SEC-2:** the cached Adventure, the Trail buffer and the Check-in queue still sit in the storage file that backups include, now that the session has moved to the Keychain.
3. **SEC-3:** the hosted captcha is still off, so anyone can spend the project's 30 Auth emails an hour and hold back every confirmation link and recovery code.

## 2. Threat model

- **Assets:** the safety promise (an Alert goes out when a Deadline passes and only the Adventurer can stop it); the live Trail, the destination and the Deadline; the Profile with its medical notes, and the contacts' addresses; the sessions; the budget and reputation of Resend and Twilio.
- **Boundaries:**
  - The phone and PostgREST, through the publishable key and the user's JWT. Only `public` and `graphql_public` are exposed.
  - The Postgres roles `anon`, `authenticated`, `service_role` and the definers of `commands` and `private`.
  - `deliver`, with `verify_jwt = false`, gated by `DELIVER_SECRET` and the HMAC callback token.
  - Twilio and Resend; Supabase Auth's own SMTP.
  - barry.support on GitHub Pages: the Trail Map page with the token in the fragment, the confirmation page, OpenFreeMap for tiles; Cloudflare Turnstile inside the app's WebView.
  - CI and the Pages deploy.
- **Attackers:** another Adventurer reaches PostgREST and every command; an anonymous caller reaches `trail_map`, `deliver` and Auth; an Emergency Contact holds a token; someone near the phone reaches its storage, backups and URL schemes; the supply chain reaches npm, Deno, the Actions and the tile server.

## 3. Findings

### SEC-1 · One Active Adventure can make Barry send any number of messages, with text the attacker chooses, to any number of addresses

**High** · CWE-770, CWE-799 · OWASP API4:2023 Unrestricted Resource Consumption, API6:2023 Unrestricted Access to Sensitive Business Flows · **proven**

The limits of `858afd5` (10 contacts, 5 per Adventure, 5 Starts a day, bounded text) bound the Starts, but not what happens between a Start and the Check-in.

**Where:**

- `supabase/migrations/20261028120100_message_limits.sql:94` and `:115`, in `commands.save_adventure`: every change of the destination of an Active Adventure enqueues a Plan Update to every contact whose Heads-up went out, with no limit on how often:
  ```sql
  v_plan_changed := a.stage <> 'planned'
    and a.destination is distinct from p_destination;
  …
  perform private.enqueue_to_contacts(a.id, 'plan_update', null, a.plan_revision);
  ```
  It cancels only the Plan Updates still `pending`, and `deliver` is kicked after every command, so each change a few seconds apart goes out on its own.
- `supabase/migrations/20261015082020_core_tables.sql:172`: `grant update (name, phone, email, removed_at) on public.emergency_contacts to authenticated;`. An address can be edited in place while the contact is in use, because `private.guard_contact_removal` checks only `removed_at`. `private.reconcile` (`20261015082022_reconcile.sql:48`, latest in `20261027120000_drop_reminder_and_overdue_notice_kinds.sql`) then owes a Heads-up to the new address, since the outbox key includes `to_address`.
- The phone check still takes any E.164 number, so the same path reaches any country by text message, at Barry's cost, once text messages are on.

**Attack path:**

1. The attacker signs up, adds 5 contacts and starts one Adventure (one of their 5 Starts).
2. In a loop, they `PATCH /rest/v1/emergency_contacts?id=eq.<own contact>` with a new `email` (or `phone`), then call `save_adventure` with a new destination such as `Visit https://evil.example/<n> now`.
3. Each round sends a Heads-up to the new address and a Plan Update to all 5 contacts, from `🐶 Barry <help@barry.support>`, with the destination in the subject.

The probe proved it against the local stack. One Start and 20 rounds three seconds apart left `heads_up|sent|25|25` and `plan_update|sent|100|24` (kind, status, rows, distinct addresses) in `messages`. Mailpit held 120 emails whose subject reads `P is heading out to Visit https://evil.example/19 now`. Nothing was refused.

**Gain:** the same as the morning's SEC-1, which the limits were meant to close. Spam and phishing to strangers from Barry's sender with the attacker's link, a cost run-up on Twilio, and with enough volume a suspended or throttled sender, which delays the Alerts of every Adventurer (harm 1). `claim_messages` now takes Alerts first, which helps only while the provider still accepts mail.

**Source:** OWASP API Security Top 10 2023, API4 and API6.

**Fix:**
- Bound the Plan Updates per Adventure, for example at most one per contact every 10 minutes, coalescing the rest as the spec already does for changes before a Plan Update goes out.
- Bound the distinct addresses one Adventure (or one account per day) may reach, or refuse an address change on a contact in use, as the spec already says ("The copy is not typed over", `docs/spec.md:42`). The app's `saveContact` sends `email` and `phone` on every update, so the server side needs a check that they did not change rather than a revoked grant.
- Allow text messages only to the countries Barry serves.

**Outcome:** fixed in `e23a463`, on the author's request (it is a rate limit, which rule 2 leaves to them). `supabase/migrations/20261029090000_pace_updates.sql`:
- an address gets at most one Plan Update and one Deadline Update in 15 minutes (`private.update_pace`); changes in between wait and become one message with the latest Plan or Deadline;
- one Adventure reaches at most 10 different contacts over its time, counting those swapped out again (`too_many_contacts`);
- `private.guard_contact_address` refuses a changed email or phone on a contact an Active, Overdue or Alerted Adventure uses (`barry:contact_in_use`). The app never changes an address, so honest Adventurers see no difference.

The probe run again: the address `PATCH` answered `400 barry:contact_in_use`; the sixth swap answered `too_many_contacts`; 20 destination changes sent one Plan Update per contact, cancelled 95 and held the latest one back 15 minutes; Mailpit received nothing at the rotated addresses. `supabase/tests/database/pace.test.sql` pins it. `npx supabase test db` (17 files, 287 tests) and the full e2e suite (75 tests) pass.

Left open: text messages still reach any country. Which countries Barry serves is the author's call, made in Twilio's Geo Permissions or with a check on the number. A contact who never agreed still cannot stop the messages of an Adventure in progress, but now gets at most 8 updates an hour from it.

### SEC-2 · The cached Adventure, the Trail buffer and the Check-in queue sit in a storage file that iOS backups include

**Low** · CWE-312, CWE-922 · MASVS-STORAGE-1, OWASP Mobile Top 10 2024 M9 · **certain**

**Where:** `src/lib/storage.ts:1-3` has `import 'expo-sqlite/localStorage/install'; export const storage = localStorage;`. The session moved to the Keychain in `911e040` (`src/lib/auth-storage.ts`, `AFTER_FIRST_UNLOCK_THIS_DEVICE_ONLY`), but `barry.inProgressAdventure` (`src/lib/barry/adventure-cache.ts`: destination, Deadline, contacts' names and addresses, last position), `barry.trailBuffer` and `barry.pendingCheckIns` still go to this file.

**Attack path:** someone with an unencrypted Finder backup, a jailbroken phone or the victim's iCloud backup reads the file.

**Gain:** where the Adventurer is going, until when, the contacts' addresses and up to the last readings of the Trail. No session any more, so nothing can be changed.

**Source:** OWASP MASVS-STORAGE-1.

**Fix:** exclude the file from backup and give it `NSFileProtectionCompleteUntilFirstUserAuthentication`, or keep these values in the Keychain too.

**Outcome:** skipped, rule 2 (moving data to another storage is the author's decision).

### SEC-3 · While the hosted captcha is off, anyone can spend the project's Auth emails and hold back confirmation links and recovery codes

**Low** · CWE-770 · OWASP API4:2023 · **likely**

**Where:** `supabase/config.toml:459-462`:
```toml
[remotes.hosted.auth.captcha]
enabled = false
provider = "turnstile"
```
with `email_sent = 30` under `[remotes.hosted.auth.rate_limit]` (line 442). The comment says to switch it on once a build with `EXPO_PUBLIC_TURNSTILE_SITE_KEY` is out; `eas.json` already carries the site key for the preview and production profiles.

**Attack path:** an anonymous caller with the publishable key calls `POST /auth/v1/signup` with 30 made-up addresses an hour, or `/auth/v1/recover` for real ones. Every call sends an email from Supabase's SMTP and counts against the project-wide `email_sent`.

**Gain:** no new account can be confirmed and no recovery code goes out while the budget is spent (harm 3), and strangers receive Barry confirmation emails. It does not reach the Alerts: those go through `deliver` and Resend, not Auth's SMTP.

**Source:** Supabase Auth production checklist (captcha), OWASP API4:2023.

**Fix:** switch `[remotes.hosted.auth.captcha] enabled = true` and run `node scripts/hosted-auth.mjs`, once the Turnstile build is in the Adventurers' hands.

**Outcome:** fixed in `821ebeb`, on the author's request: `[remotes.hosted.auth.captcha]` has `enabled = true`, and `docs/hosted-supabase.md` says when to push it. It takes effect only once `node scripts/hosted-auth.mjs` runs with `AUTH_CAPTCHA_SECRET` in `supabase/.env.hosted`. Run it only once the Adventurers have the build with `EXPO_PUBLIC_TURNSTILE_SITE_KEY`: a build without it shows no widget and could not sign in, sign up or ask for a recovery code.

## 4. Hardening notes

**Database:**
- Functions in `private` keep the default `EXECUTE` for `PUBLIC` (`enqueue_to_contacts`, `reconcile`, `record_position`, the new `guard_contact_count`, `max_contacts`, …). They are unreachable: `private` grants no `USAGE` to `anon` or `authenticated` and is not exposed.
- `private.guard_contact_count` counts without a lock, so two inserts in parallel can pass at 10 and leave 11 contacts. Nothing follows from it: an Adventure still takes at most 5.
- `anon` and `authenticated` hold `USAGE` on `net` and select on its queue, which briefly holds the `Authorization: Bearer <DELIVER_SECRET>` header of `kick_deliverer`. Unreachable while `net` is not an exposed schema.
- `private.tick_error` keeps an `adventure_id` and an error text after the account is deleted.

**`deliver`:**
- `DELIVER_SECRET` (`kick.ts:4`, `authorization === \`Bearer ${secret}\``) and the callback token (`delivery-report.ts:33`, `token !== (await reportToken(…))`) are compared with `===`/`!==`, not in constant time (CWE-208). Over the network with HMAC-length values this is impractical to exploit.

**Auth:**
- `minimum_password_length = 6` and `password_requirements = ""` reach the hosted project.
- Leaked password protection is a dashboard setting I could not see.

**The app:**
- The Turnstile WebView (`src/components/captcha.tsx`) allows `originWhitelist={['https://*', 'about:srcdoc']}`, so a link inside Cloudflare's widget opens any https page in the sign-in screen. Its `onMessage` only ever sets a captcha token, so a foreign page gains nothing.
- The Keychain keeps the session after the app is deleted; a reinstall on the same phone finds it again.
- Every iOS variant has `NSAllowsLocalNetworking` from Expo's template. There is no `NSAllowsArbitraryLoads`.
- The custom schemes `barry`, `barry-preview` and `barry-dev` have no universal link, so another app could claim one; the confirmation page links to `barry://sign-in`, which opens only the sign-in screen.

**The web:**
- The static pages in `web/` (`index.html`, `404.html`, `privacy.html`, `terms.html`) have no `<meta http-equiv="Content-Security-Policy">` and no `<meta name="referrer">`. They hold no token and load only their own files.

**Supply chain and CI:**
- `.github/dependabot.yml` still sets `package-ecosystem: ""`, so no update or security pull request is ever raised.
- `deliver`'s npm dependencies resolve without a committed lock (`deno.lock` is git-ignored).
- Actions are pinned by tag, not SHA, including the third-party `maxim-lobanov/setup-xcode@v1`.
- `trail-map.yml` gives `pages: write` and `id-token: write` to the job that also runs `npm ci`; a compromised package could already change the exported bundle, so a split job would add little.
- npm audit: `zod` (high, GHSA-mrhx-c7xc-m3w5) and `deepmerge` (low, GHSA-gcqx-w48m-w2h4) reach only `@expo/cli`, `@expo/config`, prebuild and Jest, never the app, the web build or `deliver`. npm offers only a major downgrade of `expo`, so there is no fix within SDK 58.
- `.gitignore` does not cover a plain `.env`, `.env.production` or EAS `credentials.json`.

## 5. Checked and safe

1. **Database privileges and RLS:** RLS on every exposed table; every policy uses `(select auth.uid())` with a matching `with check`; the one view `delivery_failures` is `security_invoker`. `adventurer_id` is not in the `UPDATE` column grants. `search_path = ''` on every function in `public`, `commands` and `private`. Probes as another Adventurer: Start, move, save and delete on another's Adventure all `not_found`; reading another's Adventure or contacts returns `[]`; a `PATCH` on another's contact changes 0 rows; inserting a contact for another account is refused (`400`). `claim_messages` refuses `anon` (`401`) and `authenticated` (`403`). The new limits hold: an 11th contact gets `barry:too_many_contacts`, 6 contacts in one Adventure `too_many_contacts`, a 201-character destination `400`. `private.starts` cascades with `auth.users`, and `claim_messages` now orders Alerts first.
2. **Trail Map and token:** 128 bits from `gen_random_bytes(16)`, per contact and Adventure; a guessed token gives `null` (probed). The token stays in the fragment.
3. **`deliver`:** `/` and `/status` answer `401` without a secret, with a wrong one and with `Bearer undefined` (probed). `authorizedKick` refuses an empty or missing secret (`kick.ts:4`). Plain-text email; fixed outbound hosts.
4. **Auth:** hosted email confirmation is on, anonymous sign-ins are off, refresh rotation is on, the redirect allow-list is empty with `site_url` fixed to `https://barry.support/confirmed`. `secure_password_change = true`, an eight-digit recovery code valid 15 minutes. Check Your Inbox keeps the password in memory only. The confirmation page reads only `error_code`, revokes the session a link hands the browser (`/auth/v1/logout?scope=local`) and removes the fragment with `history.replaceState`.
5. **The app:** the session lives in the Keychain with `AFTER_FIRST_UNLOCK_THIS_DEVICE_ONLY`, and the old copy is removed from the file on first read. Build values are the Supabase URL, the publishable key and the Turnstile site key, all public by design. The Turnstile page escapes the site key with `JSON.stringify` and the app parses its messages with `turnstileToken`.
6. **Web:** the exported pages carry a Content-Security-Policy (`script-src 'self'` plus two hashed inline scripts, `connect-src` only Supabase and OpenFreeMap, `base-uri 'none'`, `form-action 'none'`) and `<meta name="referrer" content="no-referrer">`. MapLibre is on 6. `scripts/trail-map-site.sh` publishes only the two pages, their assets and `web/`.
7. **Secrets:** none in the tree or the history of any branch. The `sb_publishable_` keys in `eas.json` and the old web pages and the Turnstile site key `0x4AAA…` are public by design; the test tokens are made up. `config.toml` and `seed.sql` hold local values only. No secret file is tracked; `supabase/functions/.env` and `proxy-ca.pem` are ignored.
8. **Supply chain and CI:** `package-lock.json` committed and `npm ci` in CI; no `pull_request_target`; `pr-description.yml` has `permissions: {}` and passes the title and body through `env`.
9. **Guides:** none teaches disabling RLS, the service role in the app, a committed secret or `secrets set` by hand. `docs/hosted-supabase.md` keeps the captcha secret in `supabase/.env.hosted`.
