The three things that matter most:

1. The database boundary holds: every table in `public` has row level security, `anon` holds no table privilege, and each service-role-only function is executable by `service_role` alone.
2. `deliver` authenticates every route and compares secrets in constant time.
3. The only open advisories sit in build-time packages (`minimatch`, `glob`) and their fix is a major Expo downgrade, so they wait for the next SDK.

## Threat model

- Assets: the Deadline and the Alert path, the live Trail and destination, Profiles and contact addresses, the text message and email budget.
- Boundaries: phone, PostgREST with the user's JWT, Postgres roles, `deliver` (`verify_jwt = false`), Twilio and Resend, the Trail Map page on GitHub Pages, CI.
- Another Adventurer holds a session and the publishable key and calls every RPC and table directly.
- An anonymous caller holds the publishable key, the Supabase URL and the Edge Function URL.
- An Emergency Contact holds a Trail Map link with its token.
- Someone near the phone holds a stolen phone or a backup.
- The supply chain is npm, GitHub Actions and Deno imports.

## Hardening notes

- `web/index.html`, `web/privacy.html`, `web/terms.html` and `web/404.html` carry no `<meta name="referrer">` and no Content-Security-Policy, unlike the Trail Map export (`src/app/+html.tsx:16-17`).
  They carry no token and load no foreign origin, so nothing leaks today.
  Adding both metas would keep it so if a page later links out or loads a script.
- 15 moderate `npm audit` advisories (`minimatch` and `glob` through `@expo/*` and `@sentry/bundler-plugins`) run only on a developer's or the build machine, on package files, not on network input.
  The suggested fix is a major downgrade of `expo`, so they wait for Expo's next SDK.
- Several GitHub Actions are pinned to a commit SHA with a release tag comment, which is the strongest form; no action is pinned by tag alone.
  The `ios` job's `runs-on` reads `github.event.pull_request.head.repo.fork`, a boolean, not text expanded into a script.

## Checked and safe

- **Privileges and RLS.** Exposed schemas are `public` and `graphql_public`.
  Every table in `public` has RLS on and policies `to authenticated` with `(select auth.uid())` in `using` and `with check`; `anon` has no table privilege; the views `adventure_messages` and `delivery_failures` are `security_invoker`; `private` and `vault` tables are unreachable for the app roles.
- **Security definer functions.** All carry `search_path = ''`; `claim_messages`, `settle_message`, `message_facts`, `report_delivery` and `health` are executable by `service_role` only; `trail_map` is executable by `anon` on purpose.
- **Commands.** Another Adventurer's `check_in`, `delete_adventure`, `move_deadline` and `record_trail` return `not_found`, the same as for an id that does not exist; `save_and_start_adventure` with another's contact returns `unknown_contact`; `anon` is refused on every command; a destination of 100,000 characters, a Deadline in 2099 and a latitude of 999 are refused or dropped.
- **Account deletion.** `commands.delete_account` deletes `auth.users` and the cascade removes the rest, and it refuses while an Adventure runs or a message is still on its way.
- **Trail Map.** The token is 128 bits from `gen_random_bytes(16)`, unique per contact, and a wrong token returns `null`; the function returns the name, the Plan, the Trail and the status, no ids, addresses or other tokens; the token travels in the URL fragment (`links.ts`), the page sets `Referrer: no-referrer` and a Content-Security-Policy that allows only Supabase and the map origin.
- **deliver.** The kick and `/status` check their secret first, both through `sameSecret`; the report token is HMAC-SHA-256 over the message id, 128 bits; outbound hosts are fixed (Resend, Twilio, Expo) apart from the local-only overrides; values go to Resend and Twilio as JSON or form fields, so they cannot inject headers; lengths are bounded by the guard triggers.
  An unauthenticated call to `deliver` and to `deliver/status` both answered 401.
- **Auth.** Hosted: email confirmation on, captcha on, `additional_redirect_urls` empty, `site_url` on barry.support, anonymous sign-ins off.
  Local `enable_confirmations = false` is a development value and the hosted block overrides it.
- **App.** The session sits in the Keychain with `AFTER_FIRST_UNLOCK_THIS_DEVICE_ONLY`; `EXPO_PUBLIC_*` holds only the Supabase URL, the publishable key, the captcha site key and the Sentry DSN; each variant has its own scheme; no ATS exception was found in `app.config.js` or `app.json`.
- **Secrets.** No tracked `.pem`, `.p8`, `.p12`, `.key` or `.env` file apart from `.env.example`; the history holds only the public local demo keys.
- **CI.** Workflows set `permissions`, no `pull_request_target`, pull request text reaches scripts through `env:`.
- **Documents.** No guide tells the reader to disable RLS, ship the service role key or commit a secret.
