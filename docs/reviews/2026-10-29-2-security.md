## Threat model

- **Assets:** the safety promise (Alerts, Check-ins, Deadline moves), the live Trail and Plan, Profiles and contacts, the text message budget and the sender reputation, the Vault secrets.
- **Boundaries:** phone → PostgREST (user JWT, RLS and grants) → Postgres roles (`anon`, `authenticated`, `service_role`, definers of `commands` and `private`) → pg_net → `deliver` (`verify_jwt = false`, own secret) → Resend and Twilio; the Trail Map page on GitHub Pages (no headers, token in the fragment); CI and the npm supply chain.
- **Attackers:** another Adventurer (own session, publishable key, direct RPC calls), an anonymous caller (public key, function URL), an Emergency Contact with a link, someone near the phone, the supply chain.

## Findings

### SEC-1: The hosted project accepts six-character passwords (Medium, CWE-521)

`supabase/config.toml`: `minimum_password_length = 6` and `password_requirements = ""` in `[auth]`. `[remotes.hosted.auth]` does not override them, so `scripts/hosted-auth.mjs` pushes 6 to the hosted project. No leaked-password protection is configured either.

Attack: someone who knows an Adventurer's email address (a contact has it, and the Heads-up names the Adventurer) guesses passwords against the sign-in. The hosted project has Turnstile and a rate limit of 30 sign-ins per five minutes, which slows the attack but a six-character password of a human falls to a short list. Gain: the account, so the Adventurer's Check-in and Deadline, the Trail and the contacts. Proven from the configuration. Source: [Supabase auth production checklist](https://supabase.com/docs/guides/deployment/going-into-prod), OWASP ASVS V2.1.1 (12 characters; at least 8).

Fix: set `minimum_password_length = 10` and `password_requirements = "lower_upper_letters_digits"` under `[remotes.hosted.auth]`, and turn on leaked password protection where the plan offers it, then `node scripts/hosted-auth.mjs`. **Skipped:** rule 2, a change to an Auth setting of the hosted project is the author's decision. Existing users with shorter passwords stay valid until they change them.

### SEC-2: Nothing limits where, or how widely, one account can make Barry send text messages (Medium, CWE-770, OWASP API4:2023)

`supabase/migrations/20261028120100_message_limits.sql`: `max_contacts` is 10 per Adventure, `max_adventure_contacts` 5, `max_starts_per_day` 5. `emergency_contacts_phone_check` only requires `^\+[1-9][0-9]{6,14}$`, so any country and any premium-rate range passes. `supabase/functions/deliver/senders.ts` passes the number to Twilio unchanged.

Attack: an attacker signs up (confirmed email and Turnstile on the hosted project), saves contacts with premium-rate or foreign numbers, and starts an Adventure with a Deadline in the past minutes. Each Start sends Heads-ups and then up to three Alerts to every contact. Per account and day that is a bounded but repeatable run-up; accounts are cheap. The recipient never agreed and cannot stop it. Gain: cost to the operator, and spam from Barry's number that can damage the sender reputation that the Alerts depend on (priority 1). Likely, not proven: it depends on the Twilio geo permissions of the hosted account, which the repository cannot show.

Fix: in Twilio set Geo Permissions to the countries Barry serves and block premium ranges; in the database cap distinct recipient numbers per account per day and per lifetime for new accounts. **Skipped:** rules 1 and 2, likely and a new limit.

### SEC-3: Development tooling carries high advisories that only a major SDK move closes (Low, CWE-1395)

`npm audit`: `zod` (GHSA-mrhx-c7xc-m3w5, memory exhaustion on oversized constrained collections) through `@expo/cli`; `deepmerge` (GHSA-gcqx-w48m-w2h4, prototype poisoning) through `@expo/config` and `jest-config`. The packages run only on a developer's or CI machine (`expo start`, prebuild, Jest), never in the shipped app, the Edge Function or the web build. npm offers `expo@51` and `jest@25` as fixes, which are downgrades. Proven by `npm audit --json`. `.npmrc` sets `legacy-peer-deps=true` for the SDK 58 prerelease, which lets mismatching peer ranges through without a warning.

Fix: take the patched `@expo/cli` with the next SDK 58 patch (`npx expo install --fix`) and remove `legacy-peer-deps` when SDK 58 is stable, as the comment in `.npmrc` says. **Skipped:** rule 6, no patch or minor version closes it.

### Fixed hardening note: `deliver` compared its secrets with `===`

`supabase/functions/deliver/kick.ts` (`authorization === \`Bearer ${secret}\``) and `delivery-report.ts` (`token !== await reportToken(...)`) stopped at the first differing character. Over a network the timing of a 256-bit secret is not practically measurable, so this is a note and not a finding. Fixed anyway because the rule allows it: both now use `sameSecret` in `constant-time.ts`. Commit `f6a8532`, with a Deno test. Probed after a restart of the Edge Runtime: no header and a wrong secret answer 401, the right secret answers 200.

## Hardening notes

- `supabase/functions/deliver/index.ts` reads `DELIVER_SECRET` with `!` for the `/status` route. With the variable unset the token would be keyed with an empty string; WebCrypto refuses an empty HMAC key, so the route fails with 500 and does not accept a forged report. Make it fail closed explicitly like `authorizedKick`.
- `private.*` functions that Postgres left executable to `public` (`reconcile`, `enqueue_to_contacts`, `record_position`, the `guard_*` triggers and more) are unreachable: `anon` and `authenticated` have no `USAGE` on `private`, and `private` and `commands` are not in the API schemas. Revoking `EXECUTE` from `public` would be defence in depth.
- A planned Adventure accepts a Deadline of year 9999 (`save_adventure` proven). Only the owner is affected. A upper bound would keep the clock's data tidy.
- GitHub Actions are pinned to release tags (`actions/*@v4`, `denoland/setup-deno@v2`, and the third-party `maxim-lobanov/setup-xcode@v1`), not to commit SHAs. Permissions are narrow, `pr-description.yml` passes event values through `env`, and no workflow uses `pull_request_target`.
- `.claude/hooks/session-start.sh` runs `npm install --no-save`, which can move versions inside their ranges. Development only.

## Checked and safe

1. **Database privileges and RLS.** Final state read from the live catalogue. `anon` holds no table privilege; `authenticated` can select `adventures`, `adventure_contacts`, `messages`, `position_readings` and write only `adventurer_profiles`, `emergency_contacts` and `push_devices`, each with a policy using `(select auth.uid())` and a `with check`. `delivery_failures` is `security_invoker`. Every security definer function sets `search_path = ''`. `claim_messages`, `health`, `message_facts`, `report_delivery` and `settle_message` execute for `service_role` only. `vault` is not readable by any app role. Proven: as Adventurer A, `check_in`, `move_deadline`, `delete_adventure`, `record_trail`, `start_adventure` and `save_adventure` on B's Adventure all answer `not_found`; B's rows read as 0 from every table; updating B's contact changes nothing; inserting a contact or push device for B, moving a Profile to B's id and writing `adventures` or `messages` are refused; `private`, `commands` and `vault` are not exposed; anonymous calls to `check_in` and the service-role functions fail. Length limits, coordinate checks and the 500-reading cap on `record_trail` held (2000 readings sent).
2. **Trail Map.** `trail_token` is 128 bits from `gen_random_bytes`, per Adventure and contact. `trail_map` returns the name, destination, status, positions and times only, no ids, addresses or other tokens, and nothing for a Planned Adventure or a removed contact; a wrong token returns null like a revoked one. The token travels in the fragment (`links.ts`), the page has `<meta name="referrer" content="no-referrer">` and a Content Security Policy with script hashes, and its only third-party origin is the OpenFreeMap tile host.
3. **`deliver`.** Every route checks its secret first (kick and `/status`); no secret, token or response body reaches an HTTP response; outbound requests go to fixed hosts (`api.resend.com`, `exp.host`, the Twilio host from an env that `scripts/hosted-secrets.mjs` refuses to set hosted); email and push are JSON, so no header injection; the report token is a 128-bit HMAC-SHA-256 over the message id. Proven: no header, a wrong secret and `Bearer undefined` answer 401, and so do forged `/status` calls.
4. **Auth.** Hosted: confirmations on, Turnstile on, `secure_password_change`, refresh token rotation, anonymous sign-ins off, `additional_redirect_urls` empty. The weak password length is SEC-1.
5. **App.** The session sits in the Keychain with `AFTER_FIRST_UNLOCK_THIS_DEVICE_ONLY`; no `NSAllowsArbitraryLoads`; the URL scheme differs per variant and no route acts from its parameters alone; `Linking.openURL` calls take fixed URLs; no `WebView`; `.env.example` holds only the Supabase URL and the publishable key.
6. **Web build.** `dangerouslySetInnerHTML` appears once, for the fixed `dropHtmlExtension` script whose hash the policy pins.
7. **Secrets.** `git ls-files` lists no `.env`, key or certificate file besides `.env.example`; `.gitignore` covers the secret files; history shows no secret; `scripts/hosted-secrets.mjs` prints names only and refuses `DELIVER_SECRET` and `TWILIO_API_URL` in the hosted file.
8. **CI and plugins.** See the hardening notes. Deno imports are pinned to exact versions.
9. **Documents.** No step tells the reader to disable RLS, use the service role in the app or commit a secret.
